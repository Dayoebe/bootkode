# BootKode engineering standard

BootKode helps learners, Nigeria first and internationally, develop practical technology skills. **Learn. Build. Grow.** Use real capabilities, content and records. Never invent students, results, testimonials, credentials, payment success or usage statistics.

- Inspect routes, models, policies, services, templates, tests and Git state before edits. Preserve unrelated working-tree changes. Use `refactor/*`, `fix/*` or `feat/*` branches, logical Conventional Commits and ordinary pushes; never reset/force-push shared work.
- Keep Laravel 11, Livewire 3, Blade, Alpine and Tailwind 3 conventions unless a separately justified migration is required. Livewire supplies Alpine and its plugins; do not start a second Alpine runtime. Public JavaScript is `resources/js/app.js`; dashboard charts/editors belong in `dashboard.js`.
- Read `docs/design-system.md`. Shared tokens are in `resources/css/tokens.css`, existing theme RGB variables in `app.css`, Tailwind semantic utilities in `tailwind.config.js`. Reuse Blade primitives and `ui.*` components. Do not add one-off palettes, substring color overrides, ambient animation, or another component system.
- Static UI belongs in Blade; server interaction in domain Livewire components. Keep validation/authorization in PHP and multi-record rules in existing services. Use named routes and preserve public contracts.
- Menus are not authorization. Check roles and record ownership on every sensitive action and Livewire request. Use persistent middleware plus component boot guards where appropriate. Never trust a public property for role, price, eligibility, ownership or payment state.
- `Course::publiclyAvailable()` governs discovery and enrollment. `WalletService::purchaseCourse()` is the enrollment/purchase boundary. Preserve `course_enrollments`, historical `course_user`, lesson records and issued certificate codes.
- Wallet movements must be positive, atomic and locked against stale balances. Verify gateway status/reference/amount/currency, make replays safe, and persist status/ledger/receipt together. Paystack webhook alone is CSRF-exempt and requires the configured-key HMAC. Credentials must never be public Livewire properties, Vite variables or logs.
- Existing databases contain real records. Never use destructive fresh/reset commands there. Use additive forward migrations, verify against a dedicated test database first, and back up affected records before applying compatibility changes. Preserve historical issued/revoked statuses, tokens and files.
- Tests must use an explicit database ending `_test` or `_testing`; `Tests\TestCase` refuses other MySQL databases. Do not weaken tests to hide defects. Cover access, validation, financial rollback/replay, ownership and learning eligibility when changing those rules.
- Run `php artisan test`, `npm run build`, `php artisan view:cache`, changed-PHP syntax checks and `git diff --check` as relevant. Inspect rendered behavior at 390/768/1024/1440px. Report exact limits; builds are not visual proof. Keep private fixtures out of the working database.
- Provide visible focus, skip links, labels/error associations, status announcements, dialog focus trapping/return, Escape handling and reduced motion. Keep tables bounded and controls touch-accessible. Each page owns its primary heading; the navbar title is supporting text.
- Explicit offline downloads remain supported; never implicitly cache authenticated course HTML. Preserve user/private data boundaries in all public views and search predicates.
- Avoid new dependencies without demonstrated need. Security updates may stay within compatible ranges; do not suppress advisories or force major upgrades to make an audit green. Review the current dependency audit before release.
- Maintain `docs/product-audit.md`, `architecture.md`, `design-system.md`, `refactor-roadmap.md` and `verification.md`. Mark work complete only with evidence, and document real setup/integration blockers.
